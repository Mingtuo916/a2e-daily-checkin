## 2. 平台行为事实（全部来自实测，改动前请先复核）

### 2.1 签到奖励

- 每日免费奖励固定 **+30 积分**。
- 领取路径：整页加载后站点**自动弹出** `Daily Bonus Unlocked!` 弹窗 → 点 `Claim Now`（「立即领取」）→ 过 Turnstile → **10s ~ 45s 后积分到账**。
- 积分显示在 header 左侧 `Upgrade` 上方（`span.p-icon--coin` 后跟数字），支持千分位。

### 2.2 已签到账号的三种表现（关键）

1. **重新登录后根本不自动弹窗**（最容易误判成"卡住"）。
2. 需点击 header 右上角的**「签到」图标**主动唤起面板——位置在 `Referral Bonus` 与主题切换（月亮）之间，鼠标悬停提示 `Check-in Rewards`。
3. 已签到状态下，面板显示 `Next claim available at <MM/DD/YYYY> 08:00`，**没有 Claim 主按钮**，只余 `Upgrade / SEO Bonus / Referral Bonus / Close`。

> 由此两个重要结论：
> - **每日刷新时间是本地 08:00，不是 0 点** → 脚本的任务日 key 必须按 (now − 8h) 取日期（1.0.12 已实现）。
> - 已签到状态可以**1 秒内判定**，不必等满 60 秒。这是 1.0.11 的核心提速点。

### 2.3 「签到」图标的真实结构

```html
<!-- header 右侧容器 div.ml-auto.flex.items-center 的第 3 个子 div 内 -->
<div class="flex size-8 items-center justify-center rounded-md cursor-pointer transition-colors ..."
     data-slot="tooltip-trigger" data-state="closed">
  <svg class="size-4" viewBox="0 0 16 16"> ... </svg>
</div>
```

- 它是 **`div` 而不是 `button`**，包在 Radix `Tooltip` 里，点击才是真正的业务入口。
- 稳定定位：`[data-slot="tooltip-trigger"].size-8`（并过滤 `tagName === 'DIV'`）。
- 备用定位：header / body 内 `class` 含 `size-8` 且含 `cursor-pointer|tooltip`、内部有 `svg`、文本不含 `@` 的 `div`。
- 页面会话期间该元素**始终存在**（登录/未登录都在），可以放心重试。
- 实测：`el.click()`（原生）→ **约 250ms** 弹窗出现，无需指针序列。

### 2.4 登录

- header 右上 `Sign In` → 弹窗内 `input[name="username"]` / `input[name="password"]` → 提交。
- **无验证码**。
- 登录成功后站点**整页刷新**，会话落在 cookie 里。
- 提交前需用原生 setter 写值并派发 `input`/`change`（React 受控组件），见 `setInputValue()`。
- ⚠️ 合成 MouseEvent 序列点提交按钮**不发请求**，`el.click()` 才有效。

### 2.5 退出登录（1.0.9 的重大发现）

- 站点菜单里的 `Log out` **不发任何接口请求**（network 里 0 条 logout/auth 请求），它只在客户端**删掉 `token` cookie**。
- 登录态就是那个 **非 HttpOnly 的 `token` cookie**（登录后 `document.cookie` 可见 `token=...`）。
- `localStorage.a2e_auth_storage_v2` 只是值为 `"1"` 的标记，删它没用。
- 所以脚本 `doLogout()` 现在**直接逐个删 cookie**（`token/access_token/auth_token/session/jwt`，跨 ``/host/.host/.二级域 `` 四种 domain + `path=/`），删完 `return true`，由调用方 reload 验证。菜单点击仅作 2 次兜底。

### 2.6 水合（hydration）陷阱

- 整页加载后，header **先渲染 `Sign In`**，之后才切换成账号邮箱。
- 因此"看到 Sign In"不等于未登录。脚本要求：页龄 ≥ `authSettle`(8s) 且连续 `stableFor`(1.5s) 采样结论一致，才敢判未登录；否则可能"误判未登录 → 重复登录"→ 死循环（第三轮实测踩过）。
- **1.0.10 的提速**：若上一轮刚删干净 `token` cookie（且时间在 3 分钟内），可证明"必然未登录"，直接跳过 8s 水合等待（`K_LOUT` 标记）。

### 2.7 Radix 交互特性

| 目标 | 可行方式 |
|---|---|
| 普通按钮、菜单项 | 原生 `el.click()` ✅ |
| Radix `dropdown-menu-trigger`（账号按钮） | `el.click()` ❌ 打不开；必须 `pointerdown → mousedown → pointerup → mouseup → click` ✅ |
| Radix `tooltip-trigger`（签到图标） | 原生 `el.click()` ✅（1.0.11 实测） |
| `[role="menuitem"]` | 原生 `el.click()` ✅ |

> 曾怀疑"Tampermonkey 沙箱跨 realm 合成事件失效"，**已证伪**：用隐藏 iframe 的 `contentWindow.PointerEvent` 派发同样序列，菜单正常弹出。真实原因是 `el.click()` 对 Radix 触发器无效 + 「Log out」本身不发请求。

### 2.8 平台风控

- **单 IP 最多约 4 个账号登录**，超出后出现限制类提示（"操作频繁 / 上限"等）。
- 处理策略（当前）：脚本遇到限制文案时**不退出、不推进索引**，重试上限 3 次；用尽才跳过该账号。用户侧通过**手动切换代理**续跑。
- 未做自动化分片（预留：按 4 个一批 + 长间隔；或检测限制后自动暂停）。

### 2.9 账号与凭据（1.0.14 起）

- 脚本**不再硬编码任何账号/密码**。账号由页面左下角悬浮按钮（🎁 + `x/y` 角标）打开的「账号管理」面板录入。
- 存储位置：**只写 GM 存储** `a2e_accounts = [{ email, password }, ...]`（按处理顺序）。
  - 不写 `localStorage`：`localStorage` 对站点自己的 JS 可读，把密码放进去等于把凭据暴露给页面；GM 存储是扩展隔离的。
  - 只有 `GM_setValue` 抛错（存储不可用）时才退回 `localStorage['a2e_creds:a2e_accounts']` 兜底。
- 批量导入格式（每行一个，`#`/`//` 开头为注释）：`邮箱----密码`、`邮箱 密码`、`邮箱:密码`、`邮箱,密码`、tab 分隔都支持；行内没写密码时用「默认密码」输入框。同一批里重复邮箱以**后写的密码**为准。
- 删除/上移/下移只改本地顺序，不影响站点账号；顺序 = 处理顺序（想先跑哪几个就排前面）。
- 面板同时显示**今日已完成 `x/y`**：`x` = 当前列表里出现在 `a2e_done_set` 中的账号数，`y` = 列表长度；顶部进度条、悬浮角标、结束通知、菜单「查看今日签到进度」四处同源。
- 升级脚本不会丢账号（存在 GM 存储，不随脚本文件走）；换浏览器/重装 TM 前先在面板点「导出到上方」备份文本。

## 3. 脚本架构

```
(function () {
  'use strict';
  配置区：账号库（emailOf / normalizeAccounts / accountsGet / accountsSet）
          + 今日进度（doneEmailSet / todayDoneCount）
  存储 key 常量 K_*
  等待时长 T{}
  选择器 SEL{}
  工具函数：sleep / textOf / clickEl / clickMenuTrigger / findCheckinTrigger /
           openCheckinPanel / setInputValue / waitFor / waitForValue
  页面读取：getLoggedEmail / readPoints / pageToastText
  弹窗判定：getClaimDialog / getAnyDialog / getPrimaryButton /
           isAlreadySigned / isSignInLimited
  状态读写：stateGet / stateSet（GM + localStorage 双写）/ todayStr
  今日进度：doneSet / isDoneToday / markDoneToday / retryOf / setRetry / clearRetry
  流程：handleCheckIn / doLogin(account) / doLogout / waitForAuthSettled /
        planNext / advanceIndex / finishAccount / finishAll / guard（防刷新风暴）
  面板（Shadow DOM）：mountPanel / openPanel / refreshPanel / renderAccounts /
        addFromForm / importFromText / exportToText / moveAccount / removeAccount /
        repointIndexToPending / startRun / resetToday / parseAccountLines
  入口：main() + GM_registerMenuCommand（打开面板 / 查看进度 / 重置）+ 4s 自刷新角标
})();
```

### 3.1 关键状态 key（`localStorage` 前缀 `a2e_sync:`，同时写 GM 值）

| key | 含义 |
|---|---|
| `a2e_index` | 当前处理到的账号下标（0 基） |
| `a2e_next_email` | 交接账号（索引丢失时用来纠正，防"索引乒乓"） |
| `a2e_done_date` | 今日**全部**跑完的标记（跨天自动失效） |
| `a2e_done_set` | `{date, emails[]}` 今日已完成的账号，防重复处理；**1.0.14 起 `finishAll()` 不再清空它**（它是"今日已完成 x/y"的数据源，自带任务日） |
| `a2e_run_date` | 本轮运行固定的任务日（跨 08:00 不中途切日，1.0.13） |
| `a2e_accounts` | **账号库 `[{email, password}]`（只写 GM 存储，不写 localStorage）**，1.0.14 |
| `a2e_checkin` | `{email, at}` 签到等待的跨刷新累计计时 |
| `a2e_pending_login` | `{email, at, tries}` 刚提交登录、等会话落地 |
| `a2e_retry_<email>` | 单账号重试次数 |
| `a2e_guard` | `{t, n}` 防刷新风暴（10 分钟内最多 80 次 reload） |
| `a2e_log` | 运行日志数组（控制台同时输出 `[A2E]`） |
| `a2e_logout_at` | 刚清 cookie 的时间戳（1.0.10 提速用） |

### 3.2 写盘时序（血的教训）

- `GM_setValue` 是**异步**写盘，写完立刻 `location.reload()` 会丢写入。
- 对策：`stateSet` 同时写 `localStorage`（同步、reload 也带得走），读取优先 localStorage；reload 前留 **800ms** 落盘。
- 丢失后果示例：索引没落盘 → 刷新后仍是同一账号 → 无限重复登录。
- 账号库（密码）故意**不走 localStorage 双写**（见 2.9），所以「开始 / 继续轮询」的 reload 延迟放宽到 **1200ms**，降低"刚导入就刷新"丢账号的概率。

### 3.3 单账号完整流程

```
main()
 ├ 已全部完成？(done_date == todayStr) → return
 ├ 防刷新风暴 guard
 ├ 账号列表为空 → 打开面板让用户录入 → return          （1.0.14）
 ├ 读索引/交接账号 → 目标账号
 │   └ 目标账号今日已完成 → 跳过（已登录则先退出），索引+1 → reload（1.0.14）
 ├ 读已登录邮箱
 │   ├ 有 pending_login → 等会话落地（不重复提交）
 │   └ 否则 waitForAuthSettled()（或用 K_LOUT 快路径跳过）
 ├ 已登录别的账号？
 │   ├ 在账号列表里 + 今日已完成 → 删 cookie 退出 → reload
 │   ├ 在账号列表里 + 未完成   → 纠正索引，先处理它
 │   └ 不在列表               → 删 cookie 退出 → reload
 ├ 未登录 → doLogin({email, password}) → reload
 └ 已登录 = 目标账号 → handleCheckIn(email)
        ├ 记录签到前积分 p0
        ├ 等弹窗 6s（T.claimProbe）
        ├ 没弹窗 → 点右上角「签到」图标主动唤起（1.0.11）
        ├ 仍没弹窗 → 等满本轮 slice，reload 下轮继续（累计上限 60s）
        ├ 弹窗无主按钮 → 判定今日已签到 → finishAccount('已签到')
        ├ 点「立即领取」最多 3 次 → 等积分上涨（上限 70s）
        │    ├ 涨了 → finishAccount('成功')
        │    └ Turnstile 需人工 → 通知并等 3 分钟
        └ 没涨 → 区分 已签到 / 限制文案 / 纯超时（不同重试策略）

finishAccount(email, kind, p0, p1)
  clearRetry → markDoneToday → planNext(推进索引) → doLogout(删 cookie) → reload(800ms)
  ⚠️ 顺序不能改：索引必须在退出**之前**落盘（旧版站点点 Log out 会整页跳转，杀掉后续 JS）

面板（左下角悬浮按钮）
  ├ 添加：邮箱 + 密码（同邮箱视为改密）
  ├ 批量导入 / 导出（邮箱----密码 一行一个）
  ├ 列表：状态（已完成/待处理）、上移/下移、删除、显示/隐藏密码
  ├ 顶部：今日已完成 x/y + 进度条 + 任务日 + 轮询进度 + 当前账号
  ├ 开始 / 继续轮询：索引 = 第一个未完成账号 → reload
  └ 重置今日状态：清 done_date/done_set/索引/重试（不动账号列表）
```

### 1.0.11
- **新增「主动唤起签到面板」**：登录后 6s 内没自动弹窗 → 点右上角签到图标。
- 已签到账号从"干等 60s"变为"约 7s 判定并切下一个"。
- `isAlreadySigned()` 增加 `/next\s+claim\s+available/i` 文案识别。

### 1.0.12
- **任务日界线改为 08:00**：`todayStr()` 取 `(now − 8h)` 的本地日期，与平台刷新时间对齐。
- 验证用例：07:30→前一天；08:00:01→当天；22:10→当天；次日 00:30→前一天；09:00→当天。

### 1.0.13
- **跨 08:00 不切日**：新增 `K_RUN_DATE`（`a2e_run_date`）+ `runDate()`，本轮运行固定归属一个任务日；`doneSet()/markDoneToday()/finishAll()` 全部改用 `runDate()`，`finishAll()` 写完 `K_DONE_DATE = runDate` 后清空 `K_RUN_DATE`。
  - 验证：把 `a2e_run_date` 设成昨天、`a2e_done_date` 清空 → `runDate()` 仍返回昨天且不覆写；`finishAll()` 把昨天写进 `K_DONE_DATE`、清空 `K_RUN_DATE`；`a2e_done_date === a2e_run_date`（上一轮已完成）时才允许切到今天；固定值超过"昨天"（如两天前，说明那轮早废了）会被重置为今天。
- **单例锁**：新增 `acquireSingletonLock() / renewSingletonLock() / startSingletonHeartbeat() / releaseSingletonLock()`，`localStorage['a2e_sync:lock'] = {id, at}` 心跳，`LOCK_TTL = 90s`、`LOCK_RENEW = 30s`；锁身份存 `sessionStorage['a2e_lock_id']`（刷新不变、关标签失效），`pagehide` 主动放锁。
  - 验证：标签 A 拿锁 → 标签 B（新 sessionStorage）被拒且不改写 A 的锁；`at = 0`（过期）后新标签可接管；`release` 只删自己的锁；同标签刷新后（sessionStorage 保留 id）仍能拿回自己的锁；`renew` 不抢别人的活锁。
- **`readPoints()` 健壮性**：新增 `firstNumberAfter()`（TreeWalker 取 coin 之后**最近一个**含数字的文本节点，避免相邻 span 粘连成 `3230`）+ `firstNumberIn()`；仅解析 coin 之后的文本，`closest('button')` 只作兜底，两者不一致时以紧邻文本为准并 `console.warn`。
  - 验证 9 例全过：硬币后紧跟 30→30；数字在前 `2x…30`→30（旧版读成 2）；`1,200`→1200；`0`→0（合法值）；`Free`→null；`32`+`30` 相邻→32（旧版 3230）；`30 coins · 2x bonus`→30；纯文本节点 `" 60 "`→60；无 button 容器→340。
- **读不到积分改为刷新重试**：新增独立计数 `K_RETRY_POINTS`（`a2e_retry_points_<email>`）+ `MAX_RETRY_POINTS = 2`；`(n/2)` 提示、`sleep(3000)` 后刷新，第 3 次才 `advanceIndex('读不到积分重试用尽')`；该分支**不调用 `finishAccount`**（不退出登录），成功后 `clearRetryPoints()` 归零。
  - 验证：把 `SEL.coinIcon` 改成不存在的选择器 → 日志依次出现 (1/2)、(2/2) 刷新，第 3 次跳过并推进索引；`K_RETRY`（超时/限制）与 `K_RETRY_POINTS` 互不消耗配额。
- 备注（与需求原文的一处偏差）：需求写的是 `n < MAX_RETRY_POINTS` 就重试、`n >= MAX_RETRY_POINTS` 跳过（= 只重试 1 次），但验收标准写的是"第一次和第二次刷新重试，第三次才跳过"（= 重试 2 次），两者矛盾；按**验收标准**实现为 `n <= MAX_RETRY_POINTS` 重试。

## 5. 事故记录（重要，勿重犯）

### 5.1 PowerShell 重写文件导致中文全乱码（1.0.7 → 1.0.8 期间）

- 用 `Get-Content -Raw` + `-replace` + `Set-Content -Encoding UTF8` 改版本号：PS 5.1 默认按 **GBK** 读 UTF-8 → 中文变乱码，行尾字节被当非法 GBK 双字节吞掉，CRLF 丢失（40098 → 49770 字节乱码）。
- 即便是 `-Encoding UTF8` 的 `Set-Content` 也会**写入 BOM**，`// ==UserScript==` 前多出 `EF BB BF`，有破坏元数据解析的风险。
- **规则：改这个文件一律用 `edit` / `write` 工具；确需脚本处理也必须 `[System.IO.File]::ReadAllText(..., UTF8Encoding(false))` + `WriteAllText(..., UTF8Encoding(false))` 并显式恢复 CRLF。**

### 5.2 从 Tampermonkey 存储里捞回脚本原文（恢复方法留档）

当本地文件损坏、而扩展里还装着好版本时：

1. 路径：`%LOCALAPPDATA%\Google\Chrome\User Data\Default\Local Extension Settings\dhdgffkkebhmkfjojejmpbldmpobfkfo\`
   （已装脚本正文在 `000011.log` 这类 WAL；被 Chrome 锁定时用 `[System.IO.File]::Open(..., FileShare::ReadWrite)` 复制）。
2. 解析 LevelDB log：32KB block，7 字节记录头（crc32 + len + type，1=FULL/2=FIRST/3=MIDDLE/4=LAST），拼逻辑记录 → WriteBatch（12 字节头 seq+count，entry tag 1=put + varint keylen + key + varint vallen + value）。
3. 找 key `!extdb.@source#<脚本 UUID>`，value 是 JSON `{"origin":"normal","value":"<脚本全文，\\n 转义>"}`，解 JSON 写回即得原文。

### 5.3 其它踩坑速记

- `await fetch()` 在页面评估里会 **100ms 超时**；长任务要 fire-and-forget + `window.__x` 取结果。
- 多标签同时打开站点：1.0.13 起有单例锁（`a2e_sync:lock` 心跳），第二个标签会跳过；但锁只做**同浏览器**互斥，不同浏览器/设备仍可能双跑。
- 暂停脚本的土办法：`localStorage.setItem('a2e_sync:a2e_done_date', '"<todayStr>"')`，恢复时 `removeItem`。
- 第三方自动翻译插件会改写文案，选择器**不要依赖 placeholder/纯文本**。
- 面板里的输入框会 `stopPropagation` 键盘事件，避免站点的全局快捷键对输入内容有反应。

## 6. 调试手册

### 6.1 看日志

- 控制台过滤 `[A2E]`；
- 或读 `localStorage['a2e_sync:a2e_log']`（JSON 数组，含时间戳）；
- 或打开面板看底部「最近日志」（最近 14 条）。

### 6.2 常用检查片段（页面控制台）

```js
// 当前运行状态
(() => { const g = k => localStorage.getItem('a2e_sync:' + k);
  return { index: g('a2e_index'), next: g('a2e_next_email'),
           done: g('a2e_done_set'), day: g('a2e_done_date') }; })();

// 是否还登录着（登录态 = 有 token cookie）
/(^|;\s*)token=/.test(document.cookie);

// 今日已完成账号列表
JSON.parse(localStorage.getItem('a2e_sync:a2e_done_set') || '{}');

// 手动点签到图标（等价于脚本 1.0.11 的行为）
[...document.querySelectorAll('[data-slot="tooltip-trigger"].size-8')]
  .find(e => e.tagName === 'DIV')?.click();

// 账号库（只存在 GM 存储；页面控制台读不到，请在 TM 的"存储"页看 a2e_accounts）
```

### 6.3 重置

- TM 菜单「手动重置今日状态」或面板底部「重置今日状态」：清 `done_date` / `done_set` / 索引归零 / 重试计数（不动账号列表）。
- 只想暂停：设 `done_date` 为今天；想续跑：删掉该 key，或面板点「开始 / 继续轮询」。

### 6.4 换电脑 / 备份账号

面板「导出到上方」→ 全选复制文本（格式 `邮箱----密码`）→ 在新环境的面板粘贴到「批量导入」→ 点「批量导入」。导入后建议删除备份文本。
